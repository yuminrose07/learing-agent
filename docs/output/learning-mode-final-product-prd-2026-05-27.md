## 1. Executive Summary

研学模式不是普通 `Chat` 的重皮肤，也不是课程、笔记或打卡系统。它是一个长期陪用户学习任何主题的私人研学空间：用户可以从一个词、一句抱怨、一段内容或一团模糊感开始，产品用越来越懂用户的方式把模糊直觉带入“理解铸造场”，让用户亲手把知识铸成自己的理解，再把每一次从模糊到清楚的变化收藏进“理解博物馆”。

最终产品承诺：

> 当用户想学习任何主题时，第一反应是打开研学模式，因为它最懂用户怎样从模糊走向清楚。

核心产品循环：

```text
模糊进入
  -> 研学门厅降低开口门槛
  -> 理解铸造场点燃好奇、制造碰撞、补足缺口、让用户定型
  -> 理解博物馆收藏本次理解进化
  -> 未完成分支把用户带回下一次学习
```

开发判断标准：任何功能、状态、界面、提示词、事件设计，如果不能服务“用户从模糊到清楚，并愿意下次回来继续变清楚”，都不应进入核心链路。

## 2. Problem Statement

### 2.1 谁有这个问题

首批用户只有一个人：当前产品的真实长期使用者。

这个用户不是泛化市场画像，而是一个高自驱、长期使用 AI 学习工具的人：

- 经常从模糊问题开始学习。
- 常学抽象概念、系统设计、工程机制、产品判断和复杂文档。
- 不满足于“看懂解释”，希望自己能说清楚、用起来、迁移到新场景。
- 会长期和产品互动，愿意反馈产品是否真的懂自己。
- 对普通打卡、课程进度、排行榜、泛化学习标签没有强需求。

### 2.2 当前问题是什么

普通聊天式 AI 能快速回答问题，但不稳定地帮助用户学会。它常见失败有四类：

1. **答案替代理解**
   - AI 解释得很完整，但用户只是在看答案。
   - 用户离开对话后仍然不能用自己的话讲清楚。

2. **无法接住模糊状态**
   - 用户很多时候并不知道自己要学什么，只知道“这里有一团雾”。
   - 普通输入框把用户推向“提一个清楚问题”，这会让学习在入口处断掉。

3. **不懂用户怎样学会**
   - AI 记得用户聊过什么，但不一定知道用户怎么更容易懂。
   - 它不知道用户何时假懂、何时需要例子、何时需要被反问、何时已经疲劳。

4. **学习成果没有情绪价值**
   - 传统记录只保存“学过什么”。
   - 用户真正想保存的是“我如何从不懂到懂了”，以及“我因此变成了怎样的人”。

### 2.3 为什么痛

这个问题痛在长期关系，而不是单次回答：

- 用户想学习时仍会回到通用聊天或搜索，因为研学模式还没有形成稳定偏爱。
- 学习过程容易变成“读 AI 讲义”，缺少亲手想通的成就感。
- 学完后没有一个值得保存和回看的结果。
- 下一次回来时，产品不能接上用户未完成的好奇心。
- 产品很难证明自己“比用户更懂用户怎么学会”。

### 2.4 证据和背景

本 PRD 的主要依据来自北极星讨论稿中已经收敛的三层骨架：

- 学习前：研学门厅，促成第一条学习指令。
- 学习时：理解铸造场，把模糊直觉炼成用户自己的理解。
- 学习后：理解博物馆，收藏理解进化史并驱动下一次学习。

当前项目已有 `LearningUnit`、学习卷阶段、学习指标、对齐旁路、学习卷接口与事件机制，可以作为实现承接基础。但本 PRD 定义的是最终产品体验，不受当前实现字段限制。

## 3. Target Users & Personas

### 3.1 Primary Persona：唯一首批用户

**名称**：私人研学者

**行为特征**：

- 学习起点常是模糊的：一个词、一个困惑、一段文档、一句“我好像没懂”。
- 学习过程中希望被带着思考，而不是被灌完整答案。
- 喜欢产品发现自己“哪里是假懂”“哪里卡住了”“什么方式更容易懂”。
- 学习后希望留下漂亮、可回看、能证明自己变清楚的结果。
- 下一次回来时，希望产品记得自己未完成的好奇心和已有理解。

**核心 JTBD**：

> 当我想弄懂任何主题时，我希望有一个私人研学空间能接住我的模糊好奇心，用适合我的方式带我真正说清楚，并保存我这次变清楚的过程。

### 3.2 Secondary Persona：开发团队

开发团队不是最终用户，但 PRD 需要支持其拆解工作。

**核心 JTBD**：

> 当我要开发研学模式时，我需要清楚知道每个体验阶段的产品目标、状态归属、数据事件、UI 输出、验收标准和边界，避免把愿景写进一个不可落地的 prompt。

### 3.3 非目标用户

本 PRD 当前不优先服务：

- 多人协作学习者。
- 班级、老师、团队、企业培训管理员。
- 只想要课程表和考试计划的人。
- 只想快速拿答案、不关心自己是否学会的人。
- 需要排行榜、社交分享、积分体系来驱动的人。

## 4. Strategic Context

### 4.1 产品目标

唯一北极星：

> 让个人用户真的爱上研学模式。以后想学习任何主题时，第一反应就是打开它。

产品不是追求“学习内容最多”，而是追求：

- 最低压力地开始学习。
- 最稳定地把模糊带向清楚。
- 最持续地理解用户的学习方式。
- 最有保存欲地沉淀理解成果。
- 最自然地让用户下一次回来。

### 4.2 产品定位

推荐定位：

> 一个把你的好奇心带到清楚，并收藏你每一次理解进化的私人学习空间。

更完整的工作表达：

> 一个长期陪你学习任何主题的私人研学空间。它接住你模糊的好奇心，用越来越懂你的方式带你讲清楚，并把每一次从模糊到清楚的变化收藏成你的理解博物馆。

### 4.3 与现有模式的关系

| 维度 | Chat | Ask | 研学模式 |
|------|------|-----|----------|
| 核心目标 | 快速回应 | 前置对齐 | 帮用户学会并沉淀理解 |
| 用户起点 | 一个问题 | 一个待澄清任务 | 一个模糊好奇心或学习主题 |
| 系统责任 | 回答得有用 | 问清楚再做 | 带用户从模糊走到清楚 |
| 成功结束 | 用户问题被回答 | 范围被确认 | 用户形成自己的理解展品 |
| 记忆重点 | 对话上下文 | 目标与约束 | 学习方式、理解进化、未完成分支 |

### 4.4 产品原则

1. **先激发学习欲望，再养成学习习惯**
   - 不用纪律感推动用户。
   - 通过“我好像快懂了，再来一下”推动用户回来。

2. **用户亲手铸造理解**
   - AI 不直接塞答案。
   - 产品让用户产生“这是我自己想通的”。

3. **记录变化，不只记录知识**
   - 保存用户一开始哪里模糊、怎么碰撞、如何转折、最终怎么讲清楚。

4. **温柔纠正，不评价用户**
   - 产品不说“你的学习方式错了”。
   - 产品基于行为证据调整路径，让用户感觉“它在帮我赢”。

5. **未完成感只制造好奇，不制造焦虑**
   - 结束时留下一条发光小路。
   - 不留下“一堆必须补的债”。

## 5. Solution Overview

### 5.1 顶层体验

研学模式由四个产品能力共同组成：

1. **研学门厅**
   - 让用户进入后愿意发出第一条学习指令。

2. **理解铸造场**
   - 学习时的核心场域。
   - 通过入局、碰撞、铸造、定型，把模糊直觉变成用户自己的理解。

3. **理解博物馆**
   - 学习后的长期空间。
   - 收藏理解展品、进化轨迹、能力主题展和未完成分支。

4. **学习人格镜子**
   - 横切能力。
   - 基于用户学习行为形成具体观察，帮助产品越来越懂用户怎样学会。

### 5.2 核心用户流程

```text
用户进入研学模式
  ->
研学门厅展示低压力入口和可发送指令
  ->
用户输入一个词、一句困惑、一段内容或继续历史线索
  ->
系统创建学习卷，并形成当前工作目标
  ->
理解铸造场开始：入局 -> 碰撞 -> 铸造 -> 定型
  ->
系统判断是否完成少量定型
  ->
降温，让用户看见本次已经变清楚
  ->
生成理解结晶
  ->
保存为理解博物馆展品或未完成展品
  ->
给出下一块发光的地方
  ->
下次进入时，门厅用未完成分支和展品进化召回用户
```

### 5.3 产品状态和现有学习卷的关系

开发可以沿用现有 `LearningUnit` 主链，但需要用产品语义重新解释：

| 产品语义 | 可映射现有状态 | 用户感知 |
|----------|----------------|----------|
| 研学门厅 | 无活动学习卷，或入口态 | “我可以从一团雾开始” |
| 理解铸造场进行中 | `phase = absorbing` | “我正在被带着弄懂” |
| 定型 / 淬火 | `phase = outputting` | “我要用自己的话讲出来，试试看懂没懂” |
| 展品入馆 | `phase = consolidated` | “这一块理解已经成型并被收藏” |
| 未完成展品 | `phase = stopped` 或专门的 unfinished exhibit | “这次没有完全定型，但下次能接着来” |

要求：

- Product/Application 层负责学习卷状态、展品状态、学习人格观察、未完成分支。
- Agent Runtime 只负责单轮执行，不判断产品阶段流转。
- Interface 只展示派生状态，不成为权威状态。
- Infrastructure 只提供存储、检索、外部能力，不携带产品分支策略。

### 5.4 关键对象

#### 学习卷

一次围绕某个学习目标的研学过程。它可以完整完成，也可以以未完成展品形式收束。

最小字段：

- `id`
- `session_id`
- `objective`
- `phase`
- `alignment_state`
- `source_seed`
- `created_at`
- `updated_at`
- `first_value_delivered_at`
- `current_forge_stage`
- `temperature_state`
- `completion_state`

#### 理解展品

一次学习结束后留下的收藏物。它不是总结，而是理解进化史。

最小字段：

- `id`
- `learning_unit_id`
- `title`
- `topic`
- `status`: `formed | unfinished | evolved`
- `original_fog`
- `initial_intuition`
- `collision_moment`
- `turning_point`
- `formed_understanding`
- `user_own_words`
- `capability_gain`
- `future_branches`
- `evolution_history`
- `created_at`
- `updated_at`

#### 未完成分支

一个让用户想继续的学习线索。

最小字段：

- `id`
- `source_exhibit_id`
- `branch_text`
- `branch_type`: `boundary | application | connection | misconception | next_question`
- `emotion`: `curiosity | almost_there | revisit`
- `created_at`
- `resolved_at`

#### 学习人格观察

产品基于行为证据形成的学习方式观察。

最小字段：

- `id`
- `scope`: `session | topic | global`
- `evidence`
- `observation`
- `confidence`
- `suggested_adjustment`
- `accepted_by_user`
- `created_at`

## 6. Success Metrics

由于首批用户只有一个人，指标不用于市场增长判断，而用于判断产品是否真的形成长期偏爱。所有指标初始 baseline 可在第一版上线后开始记录。

### 6.1 Primary Metric

**学习意图首选率**

定义：当用户明确想学习一个主题时，主动进入研学模式或接受研学入口的比例。

目标：

- Current：未测量。
- Target：连续 4 周内，用户 80% 以上的学习意图选择研学模式，而不是普通 Chat 或外部工具。
- Measurement：按用户自报标签、入口行为和会话主题回看统计。

### 6.2 Secondary Metrics

| 指标 | 定义 | 目标 |
|------|------|------|
| 首条学习指令率 | 进入研学门厅后发出第一条学习指令的比例 | 90% 以上 |
| 首个学习价值时间 | 学习卷创建到首个有实质学习价值输出的时间 | P50 小于 20 秒，P90 小于 60 秒 |
| 少量定型完成率 | 学习卷结束时至少形成一块用户自己的理解 | 70% 以上 |
| 自己的话提交率 | 用户在定型阶段提交自己的说法 | 70% 以上 |
| 理解展品保存率 | 完成学习后生成并保存展品的比例 | 80% 以上 |
| 未完成分支回访率 | 用户通过未完成分支再次进入学习的比例 | 4 周内可观察到稳定回访 |
| 学习人格命中感 | 用户认为观察“确实像我”的比例 | 70% 以上 |

### 6.3 Guardrail Metrics

| 指标 | 不希望发生 |
|------|------------|
| 过度提问感 | 用户觉得像考试、被盘问 |
| 过度讲解感 | 用户觉得 AI 一直在讲，自己没有参与 |
| 评价感 | 用户觉得被诊断、被贴标签、被否定 |
| 展品空壳率 | 展品只是漂亮总结，没有原始模糊、碰撞、转折、用户自己的话 |
| 入口阻塞率 | 用户进入后被迫澄清太久，拿不到学习价值 |

## 7. Functional Requirements

### 7.1 Epic A：研学门厅

**目标**：用户不用会提问，也愿意发出第一条学习指令。

#### A1. 进入研学空间

用户进入研学模式后，应看到明显区别于普通 Chat 的空间。

要求：

- 显示当前处于研学模式。
- 首屏主文案围绕“从模糊到清楚”，不围绕“提问”。
- 不要求用户先定义完整学习目标。
- 不默认展示课程列表、任务列表、打卡入口。

验收标准：

```gherkin
Given 用户打开研学模式
When 当前没有活动学习卷
Then 页面展示研学门厅
And 用户能看到低压力输入提示
And 页面不要求用户先填写学习目标表单
```

#### A2. 可发送指令模板

系统应提供可点选或可补全的第一条学习指令。

P0 模板：

- 我想搞懂一个概念：____
- 我一直卡在：____
- 帮我看懂这段内容：____
- 我只想先轻轻试一下：____
- 继续我上次没弄清楚的地方。

验收标准：

```gherkin
Given 用户在研学门厅
When 用户点击任一模板
Then 输入框填入对应提示
And 用户可以直接编辑后发送
```

#### A3. 低压力输入

用户可以用不完整输入开始。

支持输入：

- 一个词。
- 一个问题。
- 一句抱怨。
- 一段内容。
- 历史未完成分支。
- 图片或截图，若当前客户端支持图片输入。

验收标准：

```gherkin
Given 用户输入 "缓存这东西我总是迷糊"
When 用户发送
Then 系统创建学习卷
And 不因目标不够标准而拒绝开始
And 第一轮优先提供学习价值
```

#### A4. 历史接续入口

老用户再次进入时，门厅应优先显示可继续的学习线索。

推荐入口：

- 继续上次没讲清楚的点。
- 把最近收藏的展品继续进化。
- 复活一个快忘掉的理解。
- 从一条未完成分支继续。

验收标准：

```gherkin
Given 用户存在 unfinished 分支
When 用户打开研学门厅
Then 页面展示至少 1 条可继续线索
And 点击后创建或恢复对应学习卷
```

### 7.2 Epic B：理解铸造场

**目标**：用户不是旁听答案，而是把模糊直觉亲手铸造成自己的理解。

#### B1. 入局

系统不默认先讲定义，而是把用户放入一个有张力的小情境。

要求：

- 入局必须与用户输入主题相关。
- 入局应激发“为什么会这样”的好奇。
- 入局不能太长，避免首轮变成讲义。
- 如果用户明确要求直接讲定义，可以尊重请求，但仍应尽快带回理解铸造。

验收标准：

```gherkin
Given 用户说 "我想搞懂数据库索引"
When 理解铸造场开始
Then 系统先给一个能引发疑问的小情境
And 不直接输出长篇百科定义
```

#### B2. 碰撞

系统要让用户先暴露自己的直觉，并发现直觉哪里不够用。

要求：

- 至少在关键节点请求用户猜测、选择、复述或判断。
- 碰撞不是考试，不用密集提问。
- 用户回答后，系统应指出“哪部分已经对了”和“哪一块还缺桥”。

验收标准：

```gherkin
Given 用户正在学习一个概念
When 系统进入碰撞阶段
Then 系统提出一个小问题让用户暴露直觉
And 用户回答后系统不直接判错
And 系统指出可保留的直觉和需要补足的缺口
```

#### B3. 铸造

系统只补当前最缺的桥，让用户自己把解释接起来。

要求：

- 每次只补一块关键材料。
- 不输出完整百科式解释。
- 系统应把用户原有说法和补充材料接起来。
- 用户能看到自己刚刚的理解被推进，而不是被替换。

验收标准：

```gherkin
Given 用户的回答缺少因果关系
When 系统进入铸造阶段
Then 系统只补足该因果桥
And 邀请用户用补足后的桥重新讲一遍
```

#### B4. 定型

一个理解真正定型，不只是用户能复述，而是能用自己的话稳定讲出来，并至少通过一种小检验。

定型条件：

- 用户能用自己的话讲清楚本次理解碎片。
- 用户能解释一个为什么。
- 用户能识别一个边界、误用场景或换一个小场景试用。

验收标准：

```gherkin
Given 用户完成一轮铸造
When 系统请求用户定型
Then 用户需要提交自己的理解版本
And 系统判断是否已满足本次少量定型
And 不满足时回到打磨，而不是直接生成展品
```

#### B5. 火候感控制

系统应维持用户处于“差一点就懂了”的温度。

需要识别的状态：

- 用户愿意猜。
- 用户抗拒输出。
- 用户复述漏掉因果。
- 用户需要例子。
- 用户需要结构。
- 用户卡在边界。
- 用户开始疲劳。
- 用户已经跨过一小步，需要降温。

要求：

- 讲太快时，转向小问题或用户复述。
- 问太多时，转向补料或例子。
- 用户疲劳时，降低难度或收束。
- 用户刚刚跨过一小步时，先降温，不立刻加码。

验收标准：

```gherkin
Given 用户连续两次表示 "我不知道"
When 系统继续教学
Then 系统降低火候
And 给出更小的问题或更具体的例子
And 不继续追问同等难度问题
```

#### B6. 少量定型

第二层不追求一次把主题讲完，每次只铸成一块。

要求：

- 系统应明确本次要定型的“理解碎片”。
- 单次学习结束时可以只形成一个展品胚胎。
- 不因主题很大而追求一次完整覆盖。

验收标准：

```gherkin
Given 用户输入一个很大的主题
When 系统开始学习
Then 系统选择一个可定型的小切口
And 本次结束只要求该切口成型
```

#### B7. 降温

用户完成一次认知跨越后，系统应让用户看见这份清楚。

要求：

- 不立刻追加更难问题。
- 用短反馈指出用户刚刚跨过了什么。
- 为理解结晶做准备。

验收标准：

```gherkin
Given 用户成功讲清楚一个理解碎片
When 系统判断少量定型已完成
Then 系统先反馈本次已经成型的部分
And 不立即开启下一个高难问题
```

#### B8. 未完成分支

第二层结束时应留下想继续的路，而不是一堆必须补的债。

要求：

- 每次结束最多突出 1 到 3 条未完成分支。
- 分支应有好奇感，例如边界、应用、连接、反直觉问题。
- 未完成分支应能进入理解博物馆，成为下次门厅召回入口。

验收标准：

```gherkin
Given 用户完成一次学习
When 系统生成理解结晶
Then 系统提供至少 1 条下一块发光的地方
And 文案不表达为待办债务
```

### 7.3 Epic C：理解博物馆

**目标**：让每一次学习结束，都留下一个值得收藏的自己。

#### C1. 理解结晶生成

每次完成少量定型后，应生成一个理解结晶。

必须包含：

- 本次点亮了什么。
- 用户自己的理解。
- 前后对比。
- 原始模糊或误区。
- 碰撞或转折时刻。
- 产品观察到的一个学习方式小洞察。
- 下一块发光的地方。

验收标准：

```gherkin
Given 用户完成少量定型
When 系统生成理解结晶
Then 结晶包含用户自己的话
And 包含原始模糊与当前清楚的对比
And 包含下一块发光的地方
```

#### C2. 理解展品入馆

理解结晶应保存为理解博物馆展品。

要求：

- 展品保存必须基于 Product/Application 层状态，不只存在于 assistant 文本里。
- 展品详情页能展示理解进化史。
- 展品可以是 formed 或 unfinished。
- 展品不能只有 AI 总结，必须保留用户自己的话。

验收标准：

```gherkin
Given 系统已生成理解结晶
When 学习卷进入 consolidated
Then 创建对应理解展品
And 用户可以在理解博物馆中重新打开它
```

#### C3. 旧我重逢

展品详情应让用户看见过去的自己和现在的自己之间的距离。

要求：

- 显示“最开始我怎么想”。
- 显示“后来哪个问题或例子让我转弯”。
- 显示“现在我能怎么说”。
- 不羞辱原始误解，不把过去的错误当失败。

验收标准：

```gherkin
Given 用户打开一个展品
When 展品详情渲染
Then 用户能看到原始状态、碰撞时刻、成型版本
And 文案不评价用户笨或学得差
```

#### C4. 展品进化

一个展品后续可以继续进化。

进化方向：

- 能解释边界。
- 能识别误用场景。
- 能用在真实问题里。
- 能和另一个概念连接。

验收标准：

```gherkin
Given 用户从旧展品继续学习
When 新学习完成
Then 系统更新该展品的 evolution_history
And 不覆盖旧版本
```

#### C5. 能力主题展

长期形态下，理解博物馆应能把多个展品组织成能力主题展。

示例：

- 权衡展：索引、缓存、CAP、事务隔离。
- 边界展：线程和进程、接口和实现、抽象和细节。
- 变化展：微积分、增长率、反馈循环。
- 系统展：队列、状态机、事件日志、调度。

验收标准：

```gherkin
Given 用户已收藏多个相关展品
When 系统识别到共同能力主题
Then 理解博物馆可以展示一个能力主题展
And 展示该主题下用户正在长出的理解世界方式
```

### 7.4 Epic D：学习人格镜子

**目标**：产品越来越懂用户怎样学会，但不做粗糙标签和评价。

#### D1. 被动观察学习行为

系统应在不打断用户的情况下观察学习行为。

观察维度：

- 用户愿不愿意先猜。
- 用户是否习惯只看解释，不愿意输出。
- 用户复述时常漏掉什么。
- 用户更吃例子、结构、类比、问题还是反例。
- 用户卡在定义、因果、边界还是迁移。
- 用户什么时候疲劳。
- 用户在什么反馈下愿意继续。

验收标准：

```gherkin
Given 用户完成一次学习
When 系统形成学习人格观察
Then 观察必须带行为证据
And 不输出粗糙标签
```

#### D2. 具体观察反馈

学习人格镜子应输出具体观察，而不是人格分类。

好表达：

> 我发现你看解释很快，但复述时容易漏掉因果关系。下次我们可以先让你猜，再补桥。

坏表达：

> 你是视觉型学习者。

验收标准：

```gherkin
Given 系统展示学习方式洞察
When 用户阅读洞察
Then 洞察必须包含具体行为证据
And 不使用不可验证的人格标签
```

#### D3. 用户可校正

用户应能接受、忽略或修正学习人格观察。

验收标准：

```gherkin
Given 系统展示一条学习方式观察
When 用户选择不准确
Then 系统记录该反馈
And 后续降低该观察的置信度
```

### 7.5 Epic E：连续性与召回

**目标**：用户下一次回来不是重新开始，而是接着自己的认知剧情往下走。

#### E1. 门厅召回

研学门厅应展示与用户近期学习有关的继续入口。

入口类型：

- 昨天没完全讲清楚的点。
- 已经懂了 A，所以现在 B 会变简单。
- 一个能把 X 推深一层的反直觉问题。
- 一个旧展品的进化机会。

验收标准：

```gherkin
Given 用户已有学习历史
When 用户重新进入研学门厅
Then 系统展示 1 到 3 条接续入口
And 点击任一入口可开始或恢复学习
```

#### E2. 未完成展品复活

未完成展品应可以被复活。

验收标准：

```gherkin
Given 用户存在 unfinished 展品
When 用户点击继续
Then 系统创建或恢复学习卷
And 初始上下文包含上次卡住的边界和原始问题
```

#### E3. 能力成长线

系统应能把学习转译成能力变化。

示例：

> 你最近不是只学了操作系统。你正在长出一种能力：把复杂系统拆成状态、事件和约束。

验收标准：

```gherkin
Given 用户已有多个相关展品
When 系统生成能力成长线
Then 输出必须说明能力来自哪些展品证据
And 不只统计完成数量
```

## 8. Interface Requirements

本节定义界面要表达什么，不定义像素稿。

### 8.1 研学门厅

必须展示：

- 当前空间名称或状态：研学。
- 主输入框。
- 低压力入口文案。
- 可发送模板。
- 历史接续入口，若存在。

必须支持的动作：

- 发送第一条学习指令。
- 选择模板。
- 继续未完成分支。
- 打开理解博物馆。

### 8.2 学习进行中界面

必须展示：

- 当前工作目标。
- 当前处于铸造过程的大致阶段。
- 关键问题或小情境。
- 用户需要参与的动作，例如猜一下、选一个、复述、换场景试一下。
- 降温反馈。
- 收束入口。

必须支持的动作：

- 回答系统小问题。
- 请求换个例子。
- 请求讲慢一点。
- 表示不知道。
- 表示已经懂了。
- 先学到这里。

### 8.3 理解结晶页

必须展示：

- 本次点亮的理解碎片。
- 用户自己的理解版本。
- 前后对比。
- 转折点。
- 小洞察。
- 下一块发光的地方。
- 保存到理解博物馆状态。

必须支持的动作：

- 保存展品。
- 继续下一块。
- 稍后再说。
- 标记这条学习方式观察是否准确。

### 8.4 理解博物馆

必须展示：

- 展品列表。
- formed / unfinished 状态。
- 展品详情。
- 进化轨迹。
- 未完成分支。
- 能力主题展，若已有足够展品。

必须支持的动作：

- 打开展品。
- 从展品继续学习。
- 进化展品。
- 查看能力主题。

## 9. API And Event Requirements

### 9.1 API 能力需求

可复用现有 `learning-units` 接口，但最终产品需要覆盖以下能力：

| 能力 | 说明 |
|------|------|
| 创建学习卷 | 从 seed 创建一次研学过程 |
| 获取活动学习卷 | 用于恢复学习中状态 |
| 推进学习卷 | 从铸造到定型到入馆 |
| 停止学习卷 | 保存未完成状态 |
| 创建理解展品 | 学习完成或停止后形成展品 |
| 查询理解博物馆 | 列表、详情、分支、进化史 |
| 继续展品 | 从已有展品创建新的学习过程 |
| 记录学习人格观察 | 保存有证据的学习方式观察 |
| 反馈观察是否准确 | 用户校正学习人格镜子 |

### 9.2 事件要求

会话持久化必须遵守项目现有事实源约束：

- append-only JSONL 是唯一事实源。
- 不原地修改、覆盖、删除或回写既有 JSONL 事件。
- 新状态、修正、压缩结果和恢复信息必须通过追加新事件表达。
- `Agent/LLM/UI message` 只能作为派生视图或投影。

建议事件：

| 事件 | 触发 |
|------|------|
| `learning_unit.created` | 用户发送第一条学习指令或继续分支 |
| `learning_unit.first_value_delivered` | 首个实质学习输出完成 |
| `learning_unit.forge_stage_changed` | 入局、碰撞、铸造、定型、降温之间切换 |
| `learning_unit.temperature_adjusted` | 系统因用户状态调整火候 |
| `learning_unit.user_intuition_captured` | 用户暴露原始直觉 |
| `learning_unit.collision_captured` | 系统记录关键碰撞 |
| `learning_unit.user_understanding_submitted` | 用户提交自己的理解 |
| `learning_unit.fixed_piece_completed` | 少量定型完成 |
| `learning_unit.stopped_unfinished` | 用户先学到这里，保存未完成 |
| `understanding_exhibit.created` | 生成展品 |
| `understanding_exhibit.evolved` | 旧展品进化 |
| `curiosity_branch.created` | 生成未完成分支 |
| `learning_profile.observation_recorded` | 记录学习人格观察 |
| `learning_profile.observation_feedback_recorded` | 用户反馈观察是否准确 |

### 9.3 派生视图

以下内容是派生视图，不是事实源：

- 门厅推荐入口。
- 理解博物馆列表排序。
- 能力主题展。
- 学习人格镜子摘要。
- 展品详情页中的展示文案。
- 指标报表。

## 10. User Stories

### Story 1：从模糊开始

As a 私人研学者, I want to 用一句模糊表达开始学习, so that 我不用先把问题组织得很标准也能开学。

```gherkin
Scenario: 模糊输入也能开始
Given 用户在研学门厅
When 用户发送 "索引这东西我总是迷糊"
Then 系统创建学习卷
And 首轮输出包含工作目标和入局情境
And 系统不要求用户先填写学习目标
```

### Story 2：我不是旁听答案

As a 私人研学者, I want to 在学习过程中被引导先暴露直觉, so that 最后的理解感觉是我自己想通的。

```gherkin
Scenario: 系统制造碰撞
Given 用户正在学习一个概念
When 系统发现用户尚未表达直觉
Then 系统提出一个小问题或小判断
And 等待用户参与后再补关键材料
```

### Story 3：我不知道时不会被拷问

As a 私人研学者, I want to 在答不上来时被降低难度, so that 我不会感觉像考试。

```gherkin
Scenario: 用户连续不知道
Given 用户在碰撞阶段
When 用户回答 "不知道"
Then 系统降低火候
And 给一个更具体的例子或二选一判断
And 不继续追问同等难度问题
```

### Story 4：用自己的话定型

As a 私人研学者, I want to 用自己的话把理解说出来, so that 我知道自己不是只看懂了 AI 的解释。

```gherkin
Scenario: 定型失败继续打磨
Given 用户提交自己的理解
When 系统判断缺少关键因果或边界
Then 系统指出缺失的一小块
And 回到铸造阶段继续打磨
And 不直接生成 formed 展品
```

### Story 5：学完留下理解结晶

As a 私人研学者, I want to 学完后得到一个漂亮的理解结晶, so that 我能保存这次变清楚的证据。

```gherkin
Scenario: 生成理解结晶
Given 用户完成少量定型
When 学习卷收束
Then 系统生成理解结晶
And 结晶包含原始模糊、碰撞、用户自己的话和下一块发光的地方
```

### Story 6：未完成也能被保存

As a 私人研学者, I want to 在没完全学完时保存未完成状态, so that 下次可以从卡住的地方继续。

```gherkin
Scenario: 保存未完成展品
Given 用户正在学习但想先停下
When 用户选择 "先学到这里"
Then 系统生成 unfinished 展品或未完成分支
And 保存当前卡住点
And 下次门厅可以召回它
```

### Story 7：回到旧展品继续进化

As a 私人研学者, I want to 从旧展品继续学习, so that 我不是只学新东西，也能让已有理解继续变深。

```gherkin
Scenario: 展品进化
Given 用户打开一个 formed 展品
When 用户选择 "继续进化"
Then 系统基于该展品创建新学习卷
And 完成后追加 evolution_history
And 不覆盖旧展品版本
```

### Story 8：看到自己怎样学会

As a 私人研学者, I want to 看到产品对我学习方式的具体观察, so that 我能感觉它真的懂我。

```gherkin
Scenario: 学习人格观察
Given 用户完成一次学习
When 系统生成学习方式洞察
Then 洞察包含具体行为证据
And 用户可以标记准确或不准确
```

## 11. Out Of Scope

当前最终产品 PRD 明确不定义以下能力：

- 多人协作学习。
- 班级、老师、学生管理。
- 分享排行榜。
- 社交关系链。
- 通用课程市场。
- 打卡、积分、勋章作为核心驱动。
- 企业培训后台。
- 把研学模式做成通用知识库。
- 把理解博物馆做成普通笔记工具。
- 在 Agent Runtime 中直接实现产品流程编排。
- 将 UI 本地状态作为服务端真实状态。
- 原地修改 JSONL 历史事件。

## 12. Dependencies And Risks

### 12.1 Dependencies

| 依赖 | 说明 |
|------|------|
| 学习卷状态模型 | 承接研学过程、阶段、停止、完成 |
| 事件持久化 | 支撑展品、分支、观察的 append-only 事实源 |
| Mode/Profile 编排 | 区分 Chat、Ask、研学执行策略 |
| 前端研学门厅 | 承接第一条学习指令和历史召回 |
| 流式输出与元数据 | 在学习过程中展示阶段、目标、建议条 |
| 记忆与投影 | 形成学习人格观察和博物馆视图 |
| 评测样例 | 判断过度提问、过度讲解、展品空壳等风险 |

### 12.2 Risks

| 风险 | 影响 | 缓解 |
|------|------|------|
| 变成普通 Chat 加漂亮文案 | 用户感受不到学习差异 | 要求每次学习必须出现用户参与、少量定型、展品沉淀 |
| 过度提问像考试 | 用户抗拒继续学习 | 增加火候状态和降温机制 |
| 理解博物馆变成档案馆 | 用户保存后不回看 | 展品必须带未完成分支和进化入口 |
| 学习人格像贴标签 | 用户觉得被评价 | 所有观察必须有证据，并允许用户校正 |
| 展品只有 AI 总结 | 没有“我真的变了”的感觉 | 展品必须包含用户自己的话、原始模糊、碰撞、转折 |
| 产品状态和消息文本混在一起 | 后续无法恢复和进化 | 关键状态必须落 Product 事件，消息只是投影 |
| Runtime 承担产品语义 | 破坏项目分层 | PRD 要求 Product/Application 持有产品状态和编排 |

## 13. Acceptance Checklist

开发完成一个可用版本前，至少应通过以下验收。

### 13.1 主路径验收

- 用户可以进入研学门厅。
- 用户可以用模糊输入创建学习卷。
- 首轮有实质学习价值，不默认阻塞澄清。
- 学习过程中出现入局、碰撞、铸造、定型中的关键体验。
- 用户至少一次被邀请用自己的话表达理解。
- 系统能根据用户“不知道 / 太快 / 换个例子”调整火候。
- 学习结束生成理解结晶。
- 理解结晶保存为理解展品。
- 下次进入门厅能看到至少一条可继续线索。

### 13.2 分层验收

- Product/Application 层拥有学习卷、展品、分支、学习人格观察的权威状态。
- Agent Runtime 不直接判断研学门厅、理解博物馆、学习人格镜子等产品语义。
- Interface 不把本地展示态当成服务端真实状态。
- Infrastructure 不携带业务策略分支。
- JSONL 事件只追加，不覆盖旧事件。

### 13.3 体验验收

- 用户不会在入口被迫填写完整目标。
- 用户不会在学习时只看 AI 讲义。
- 用户不会在答不上来时被继续拷问。
- 用户完成后能看到自己从模糊到清楚的距离。
- 用户能从未完成分支继续。
- 学习人格观察像“被看见”，不是“被评价”。

## 14. Recommended Development Slices

### Slice 1：最小研学闭环

### Slice 2：理解博物馆基础

目标：学习成果可回看。

包含：

- 理解展品对象。
- 展品列表。
- 展品详情。
- formed / unfinished 状态。
- 从展品继续学习。

### Slice 3：火候感与未完成分支

目标：学习过程更像被懂。

包含：

- 用户状态识别。
- 降温策略。
- 未完成分支生成。
- 门厅召回。

### Slice 4：学习人格镜子

目标：产品开始懂用户怎样学会。

包含：

- 学习行为观察。
- 证据化洞察。
- 用户反馈准确性。
- 后续学习策略调整。

### Slice 5：能力主题展

目标：长期收藏理解世界的方式。

包含：

- 能力主题聚合。
- 展品间连接。
- 能力成长线。
