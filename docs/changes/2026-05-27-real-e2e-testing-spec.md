## 变更类型

- 新建文档

## 背景

- 后续该项目将持续基于真实数据集执行端到端测试，而不是只依赖脚本化回放。
- 需要把“数据集放哪里、运行结果放哪里、证据包放哪里、以后怎么复用”收敛成仓库内的稳定规范。
- 该规范需要在未来真实测试任务中被重复遵守，因此比一次性对话结论更适合作为仓库模块落盘。

## 设计选择

本次选择“仓库内规范模块”，而不是单独 skill。

原因：

- skill 更偏助手能力和跨仓库复用。
- 当前需求更偏“本仓库以后所有真实 E2E 都必须遵守什么”。
- 仓库内规范更容易和代码、测试、变更记录一起演进。

如果未来出现跨仓库复用需求，再考虑把这套规范抽象成通用 skill。

## 预期收益

- 真实数据集不再散落在临时对话或脚本里。
- 每次真实 E2E 运行都有固定结果目录和证据结构。
- 后续讨论“是否回归”“和上次比有没有变差”时，可直接基于本地结果包比较。
- 已知真实问题能稳定沉淀进回归集，而不是靠人工记忆。
