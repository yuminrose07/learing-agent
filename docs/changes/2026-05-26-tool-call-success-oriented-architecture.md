# 2026-05-26 Tool Call Success-Oriented Architecture

## 背景

- 当前问题已经明确不是单个工具 Bug，而是整个工具调用主链的正确性问题。
- 目标被重新收口为：
  - 用户不能感知到工具失败
  - 工具调用不能空返回
  - 所有失败都应在系统内部完成自愈

## 本次产出

- 新增正式方案文档：
  - `docs/output/tool-call-success-oriented-architecture-2026-05-26.md`

## 方案重点

- 把工具调用从“执行导向”改成“成功导向”
- 统一失败语义，不再区分异常失败和结果失败
- 引入统一的恢复链，而不是把 fallback 写散到各个工具里
- 在工具结果进入 session 主链前增加提交收口层
- 增加最终回答保护，禁止同步 `/chat` 空返回

## 推荐实施顺序

- P0：
  - 统一 `ToolOutcome`
  - 修失败判定主链
  - 补结果级恢复链
  - 增加结果提交器
  - 增加最终回答保护
- P1：
  - provider fallback 标准化
  - 恢复策略模板化
  - 可观测性与指标体系

## 说明

- 本次只输出架构方案，不包含代码实现。
- 后续如进入实施阶段，应优先改 Runtime 与 Product/Application 交界的工具主链，而不是继续给单个工具打补丁。
